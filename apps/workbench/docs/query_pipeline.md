# Query分类、风险判断与相似案例匹配

固定六类场景：ST1海报短信社交文案，ST2直播短视频口播，ST3产品介绍详情，ST4说明会客户活动，ST5培训电销回访，ST6处罚与后台事实。风险标签固定27类。

## 输入与候选

解析文件或文本，登记页码、全文偏移和来源哈希；识别场景、说话人、否定/禁止立场及产品作用域。场景可由用户指定；自动分类先用规则，必要时交Pi/DeepSeek。

强规则处理明确机制，字词ngram轻量模型补充三态和27标签候选。该模型用400条开发Query训练，候选用于触发语义复核；最多两个相关开发示例校准标签含义。

当前400条开发参考已经逐条自复核后重新训练。规则不再将近义、上下位标签自动并入结论；财务不实、虚列套费、客户字段、人员资格分别核对。含“是否、无法判断”等待核条件的强命中仍进入语义检查。全文反例或已否决方案的逐字立场说明随分批窗口传递，不借用其他段落的业务事实。

## Pre、Post与自适应

- Post：先审查材料，再用判定后的行为和标签查案例。
- Pre：先用本地候选查案例，将过门槛摘要提供模型理解行为。
- 自适应：按歧义、条件及机制决定Pre，按作用域/机制复用Post案例池，允许一次定向覆盖补查。

Pi使用结构化`submit_result`工具，原生提交最多两轮。返回当前句、独立机制、标签与条件判断；原文编号由程序还原并检验作用域。风险、无明确风险、信息不足分别保存。模型确认标签不与本地候选机械取并集。

短文整篇提供上下文；1600字且至少20句的长文先通读初筛，正常句以显式区间提交。规则和轻量模型候选、上下文依赖及不确定句强制详细核查。每个原句必须属于一个分区，失败回到完整复核；详细核查按字符和句数预算分批并发。上下文压缩、原文编号和共享案例池减少重复输入输出。结构化输出预算随目标数增长，证据字段限定合法原文编号。补查只重送未完成或未覆盖的目标；未涉及机制允许空依据，已成立风险仍须完整原文和必要条件。修复失败保留有效结果和复核未完成状态。

## 检索与排序

BM25、同模型Qwen文档/query向量、中性行为表达经RRF融合后统一排序，可选融合原序、Qwen及Pi/DeepSeek。Embedding缓存按模型隔离，机构、主体、时间等筛选独立可用。

判定后的风险句匹配案例；自适应按机制共享和软约束召回，避免错误候选标签提前排除相关案例。返回原文证据、来源、分数和具体行为对应理由。相似度不参与当前风险概率计算。

## 输出与维护

API4.0返回原文高亮、逐句/机制三态、标签、引证、缺失事实、整改建议、案例及阶段耗时。Web增加策略选择、原始PDF、字段来源、主体关系、HTML/JSONL导出与效果页。

新增案例经过保险筛选和多主体拆分，证据注册与案例写入统一提交。新增语料后需离线刷新Qwen索引，当前没有自动向量热切换。
