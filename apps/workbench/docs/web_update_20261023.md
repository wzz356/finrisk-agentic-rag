# Web 更新（2026-10-23）

## 发送口令的误报修复

旧规则会从“发送”的“送”字开始匹配，把“发送暗号【旅行险年卡】”中的“卡”误当作赠品。
赠礼强规则现在区分信息发送与赠礼动作，并要求具体利益对象，例如红包、购物卡、体检。
“发送暗号【旅行险年卡】，获取保障方案”不再由这条规则判为赠送利益；“投保后发送红包”
和“发送口令后投保送购物卡”仍然命中。此修复不代表对整篇材料中其他表述的合规背书。

## 首页右上角

原“本地工作区”替换为两行：`YYYY年MM月DD日`、`今日已爬取 N 个案例`。日期和采集数
由 `/api/collection/status` 的 `today`、`today_crawled_cases` 返回，按北京时间刷新，
页面每分钟更新一次，重新进入页面时也会刷新。窄屏将导航移到第二行，保留日期和计数。

计数使用已入库官网案例的 `collected_at`，按 `file_id` 去重；缺少该字段时依次使用
`source_file`、`case_id`。同一文书多个被处罚主体只计一次，手动录入、重复和失败记录
不增加计数。北京时间跨日重新统计，进程重启后沿用持久化数据。接口读取失败显示“—”。
无时区的历史时间按北京时间解释；缺少或无效的采集时间不计入当日。

## 验证与部署

本地 250 项 Python 测试、31 项 Node 测试通过，Ruff、Mypy 与 JavaScript 语法检查通过。
新增测试覆盖联系指令、真实赠礼、混合话术、北京时间日界线、按文书去重和重启后统计。

Linux 环境下同样通过 250 项 Python 测试。公网完整旅行险原文回归中，“发送暗号”一句
没有风险标签，“秒杀市场上其他的无良产品”保留“贬低竞品”和“绝对化表述”；补充的
“发送暗号……投保再送购物卡”仍识别赠送利益。原文此次返回 14 句、1 句风险句、
整体中风险，无运行告警。页面在桌面、手机和平板断点检查日期与计数布局。
