# 案例原文 PDF 与录入修复（2026-10-23）

风险查询中的相关案例、案例管理及录入结果共用同一详情抽屉。
“打开原文 PDF”按钮移到标题和标签下方，新标签页内联打开原件。
没有 PDF 的网页采集材料显示来源网页或现有来源文件，不将 HTML 冒充 PDF。

## 历史原件绑定

原库 15,620 个主体案例中，只有 1,464 条记录带有 `raw_source_file`，导致很多案例没有原件入口。
`scripts/build_source_pdf_index.py` 对本地 10,000 份 PDF 与证据登记库逐份匹配，
生成 9,639 份来源文书的映射；同文书多个主体共用原件。
匹配只忽略 Unicode 等宽形式、排版空白和末尾网站“手机扫一扫打开此页”提示，
要求其余完整正文相同，不按机构名称或标题猜测。

运行映射位于知识库根目录 `source_pdf_index.json`；不改冻结案例、原文和向量索引。
读取时再核对来源 SHA、PDF 文件 SHA 和允许目录，兼容原有 Linux 长文件名短名映射。
映射作为本地运行资产单独部署，不提交原始 PDF 或全库映射到 GitHub。

## 录入失败原因及修复

实际复现：平安人寿官网 PDF 中的公司名为“……四川\n分公司”，模型返回连写公司名；
处罚事实和引文也会去掉 PDF 行中空格，旧版直接做子串判断，因此返回 422。

- 对主体名和事实引文只容忍空白差异，重新绑定真实连续原文；数字、用词、标点变化和拼接引文仍拒绝。
- 结果未通过校验时在 Pi Agent 路径内最多补正一次；不把未核验内容作为成功案例写入。
- 上传临时文件和落盘原件使用短文件名，避免长中文文件名超过 Linux 限制；原文件内容不变。
- 损坏、加密 PDF 返回明确读取错误。
- 重复文件或相同处罚主体保持 409“已入库”，不重复写入。
