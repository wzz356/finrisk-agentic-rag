# 比赛任务交付映射（2026-10-19）

固定27类风险、ST1–ST6六类Query场景，底层使用Pi Agent。Web使用新库9,639份处罚文书、15,620个主体案例。

| 比赛任务 | 本地实现 | 验证和范围 |
|---|---|---|
| 原始材料解析 | PDF正文和扫描页OCR回退；图片、DOCX、文本与表格输入；保存页码、偏移和来源哈希 | 原始10,000份PDF均可读出正文；本轮无须重跑OCR |
| 案例抽取和拆分 | 多主体拆分、保险相关筛选、27标签、处罚金额和日期映射、字段来源、监管与主体关系 | 500份文书绑定原始PDF；真实API试验3主体保留2个保险主体 |
| 混合检索 | BM25、同模型Qwen文档/query向量、行为表达融合；融合原序、Qwen、DeepSeek三种排序 | 独立200Query、500候选上计算Hit、Recall、MRR和NDCG |
| 合规审查 | 六场景、规则及轻量候选模型、逐机制三态、原文校验、定向覆盖补查、整改建议 | 默认DeepSeek重排＋自适应pre/post；Pre、Post保留 |
| 交互与导出 | 高亮、案例筛选、字段来源、主体关联、原始PDF、HTML报告、比赛JSONL、效果页 | 沿用原有颜色、排版和导航风格 |
| 训练与评测 | 500份不同文书的500候选条目；400开发Query；200测试Query评分 | Codex逐条自复核，开发/测试种子文书不重合；参考修改留档 |

真实数值和API口径见[本轮技术及效果报告](competition_upgrade_20261019.md)，划分见[数据集说明](dataset_card.md)。

当前没有人工逐字段正确率评测、专用手写模型、全库专家相关性金标，以及上传后全量Qwen向量自动热更新。新增语料后运行离线索引构建命令刷新。

源码、新评测集和冻结结果随GitHub分发；密钥、PDF、全量索引及运行日志保存在本地。本轮没有远程部署。
