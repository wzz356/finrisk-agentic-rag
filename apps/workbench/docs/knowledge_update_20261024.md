## 上游更新与本地采用

- 来源、主体案件、行为责任与证据分别保存，按稳定 ID 关联。赛事分区从 9,639 份补到 10,000 份：补 360 份原预留材料，并从缺少 TXT 的 PDF 恢复 1 份。本地扩展编号 F010000 没有冒认官方缺号。

- 新增保险范围规则以主体、明确任职与业务事实提供线索；保险简称、银行代销保险可以进入候选处理，法律名称和监管机关名称不能充当保险业务事实。无关键词材料保留范围复核，不再静默丢弃。规则返回原文坐标、未知项及 pending 状态，不能签发审核批准。
- 本地额外修正上游的客户身份边界：`甲科技公司（甲保险公司客户）`不能仅因括号内出现保险公司就当作保险机构。新增回归覆盖该情形。
- 来源证据继续逐字回读，使用 Unicode 码点半开区间。新增发布锁绑定原始分区、官网分区、证据数据库、来源别名与 PDF 映射。P0 法规与机制仍使用自己的冻结版本锁，避免将新案例版本冒充新的法规审核。
- 官网管理列表保留所有范围；保险审查默认只使用获保险关联候选标记的处罚材料。400 份明确非保险、37 份关联不明及许可等材料保留原件和状态，不强加保险风险标签。拟处罚与送达公告保留文书类型与决定状态，未改成已处罚事实。
- 当前应用继续使用 Pi 有界工具循环、BM25 + Qwen + RRF 和已有可选重排。本次没有将 BGE 向量与 Qwen 混合；上游 BGE 预生成资产仅用于核对交付。上游的 Proposer–Reviewer 真实生产适配器及完整自动发布仍未配置，本地没有把工程演练当作已启用的自动审核。

## 重建入口

先按固定清单下载六个 Release 包至一个本地目录，并准备原始 PDF、857 份官网附件以及旧法规/范围阅读资产。旧库可从历史恢复链路恢复；构建只复制必要的冻结法规和范围资产，不执行上游 Python。

```powershell
.venv\Scripts\python.exe scripts/sync_full_knowledge.py --assets outputs/kb_update_20261024 --web-archive "FinRisk_官网采集857份_20261024.zip" --legacy-root data/processed/knowledge/finrisk_v2_1_20261018 --output data/processed/knowledge/finrisk_full_20261024
# 将 FINRISK_CASE_KB_ROOT 指向新目录，随后离线构建：
.venv\Scripts\python.exe scripts/build_competition_index.py --qwen
.venv\Scripts\python.exe scripts/verify_delivery.py
```

输出目录要求不存在，避免覆盖历史数据。现有独立官网分区继续联合读取，已知重复通过映射抑制；服务器额外增量应先恢复到该分区。自动采集水位不因历史附件导入而前移。

Windows 受限环境运行测试时，将 TEMP/TMP 指向项目内 `.tmp`，并给 pytest 指定新的 `--basetemp`。应用真实推理、检索与原件验证另行记录，单元测试不代替模型效果评测。
