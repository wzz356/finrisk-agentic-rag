# Codex新旧知识维护实验：20份开发轮结论

日期：2026-10-24。模型：gpt-6.1-sol，low，原生Codex独立角色，最多3角色并行。没有调用DeepSeek，没有更新正式知识库。

## 做了什么

冻结10,000份赛事基础文书和850份官网增量，原件与归档哈希核验通过。850份完成无模型关联预检；选择100份新文书，按40份初筛无同案线索、40份有相关旧记录、20份关系／性质不明分层。此次只运行开发20份（8／8／4）；正式80份尚未运行。

每份先由Proposer读新文并检索基础库，再由独立上下文Reviewer审核；最多一次业务修订。所有动作包括排除和待核都经过Reviewer。A组保留原初稿，B组使用审核后的结果。

20份均达到本轮协议的最终审核建议通过，包括对“排除”和“待核”决定的认可，不能写成“20份均新增入库”或“准确率100%”。

D18：中国银河资产管理材料的初稿建议按非保险范围排除。Reviewer指出原文只披露“投后管理不到位”，不足以确定是否涉及保险业务；修订后改为hold，保留业务范围未知，随后复审通过。这个结果展示了审核对过强处置的约束，是否更优仍需人工核验。

D19：人保寿险吉林省分公司原文明确是“换领许可证超期”，处罚为警告并罚款1万元。两个角色均识别为处罚材料并保留候选。不能仅看到“许可证／换领”就称其为行政许可公告；此前粗分流只应作为待核线索，历史说明中的“换证公告”表述不准确。

## 验证与消耗

- 54项离线测试通过，涵盖动作审核、引用、目标版本、关系来源、批次冲突、共享预算和未知结果不得重发。
- A/B隔离投影均完成148处引文回读、撤销检查，20条旧查询在基线加增量的轻量词项视图中保持命中。正式新增查询来自未运行的80份，尚未测试，不与开发轮混算。
- 主机观察窗口约39.2分钟，包括编排、工具和队列，不是纯推理延迟；有1个快速任务的回执晚记，不能用该条计算角色时延。
- Codex账户共享用量观察从13%到17%，包含准备、开发、协调、审查及可能的其他任务，不能精确归因于42个角色。没有逐角色token账单，不编造token数或换算人民币。
- 隔离卡使用简化实验Schema，人工状态pending；不是完整八表／BGE生产发布。

## 目前能得出的结论

**可以支持：** 在10,000份只读基线上，Codex双角色能够完成20份新材料的提议、审核、有限修订、范围分流和隔离候选构建；格式及引用流程在本批稳定运行。

**不能支持：** Reviewer已显著提升准确率、已经清除了矛盾或过时知识、已经完成850份正式更新。本批没有真实重复关联、旧卡纠错或替代正例；受控16份按用户要求保持待核，未运行模型。

## 为什么暂不扩到正式80份

工程数量门槛已满足，但进一步核读发现：有相关旧记录的8份中，只有3份实际完整读取旧文。D10、D13、D15虽形成新增候选，却没有完整旧文对照。全库索引检索／未命中不能替代充分的新旧冲突核查。

因此保留此开发版本与全部原始输出，先补强相关旧候选的检索和全文回读，再核定人工参照。正式80份和受控16份保持未运行，避免把当前的覆盖不足扩大成全量结果。


公开版事后核读还发现D14、D20的范围排除理由需补充核验，不能将五份排除都当作人工确认正确。见[范围处置说明](scope-review.md)；原始统计和输出未改动。逐案材料见[HTML报告](report.html)。
