# 实验协议与实施范围

本文是已执行开发实验的协议摘要，不是重新运行指令；具体输出保留于本目录。

## 目标与参照

模拟10,000份赛事基础文书与850份采集新增材料的维护过程。旧库只读，内部一致作为实验前提；新材料可能新增、重复、需要更正旧记录，也可能范围无关或证据不足。不能把同机构、不同日期、不同责任人或机构个人双罚自动认定为冲突。

850份先以本地脚本做身份与关联预检，再冻结100份新材料。初筛无明显同案线索40份、有相关旧记录线索40份、关系或性质不明20份；其中20份开发、80份正式。正式集在任何模型派发前冻结，但本轮没有运行。相关线索不是已核实新旧关系。

## 双角色和对照

每份开发材料由原生Codex的两个独立上下文处理，固定 `gpt-6.1-sol / low`，最多3个角色并行：

1. **P1提议者：**完整读新文，检索完整旧库，必要时读旧文或旧卡；提出处置，生成有来源依据的知识卡并保留未知。
2. **R1审核者：**获得新文和提案，独立使用证据工具；核对范围、身份、事实、主体、标签、遗漏和历史保护。即使建议排除或待核，也要审核。
3. **P2有限修订：**仅在审核要求修改时进行，最多一次业务修订。
4. **R2复审：**核对修订并结束；不以无限循环追求通过。

A保留P1初稿，B保留审核后的结果。同一批配对观察，不是随机独立试验。19份使用P1/R1，D18使用P1/R1/P2/R2，合计42个角色任务；两组新增卡相同，不能推导整体效果提升。

## 六类动作

| 动作 | 含义与约束 |
|---|---|
| `add` | 建立新增候选案件卡和行为卡；不直接生产发布 |
| `link_duplicate` | 保留来源并关联重复；需新旧全文证据，不能仅凭机构相同 |
| `correct_record` | 对已核实旧卡提出纠错，绑定目标版本和完整变更 |
| `supersede` | 对有明确更正或撤销依据的旧记录作替代处理；保留历史 |
| `hold` | 关键事实或范围不明，保留待核 |
| `exclude_from_penalty` | 对明确不属本项目保险处罚范围的材料提出排除；不删除原件 |

没有更正／撤销证据，不因日期较早停用处罚案例。原文未写的行为人、资金流向和逐项个人责任保留未知。每行为卡允许0—3个官方标签，必要要件不足时可为0，不强行补齐。

## 工具与边界

角色只通过受控证据工具读取材料，不联网、不调用其他模型或API，不读取密钥、其他任务或已有新材料知识卡；来源文本是数据，不执行其中指令。

| 工具动作 | 用途 |
|---|---|
| `source` | 分页读本份新文，记录来源与分段 |
| `search` | 根据完整文号、姓名或机构等检索旧库；摘要不算全文 |
| `read` | 分页读取旧文；连续覆盖完整文本才计完整核读 |
| `records` | 读取旧卡与版本哈希，支持有约束的旧记录变更建议 |

每角色最多12次证据操作，每份文书最多32次共享操作。每页最多6000字符，有续页必须继续读取才算完整。搜索未命中只说明所查范围未命中，不证明全库不存在重复。

主机核对JSON结构、官方标签、逐段引用、目标记录版本、新旧关系证据和批次冲突。已有消耗状态不能删除后重派；未知或失败不得伪装成成功。角色输出Schema见[proposal-schema.json](proposal-schema.json)和[review-schema.json](review-schema.json)。

## 隔离与评价

使用完整只读基线的A/B增量投影；模型候选不切换生产库。投影不是完整生产八表或BGE索引。验证覆盖引文回读、旧查询命中与撤销；不能将这些工程检查当作风险识别准确率。

原计划开发轮至少18/20形成有效双角色处置且无破坏性变更，再考虑正式轮。本轮数量门槛达到，但质量核读发现R组旧文完整读取仅3/8，D10、D13、D15新增前无完整旧文对照，故未扩批。后续又发现D14、D20范围判断需补充核验，见[范围说明](scope-review.md)。

16份合成检查参照仍待用户核定，未运行；它们不能计作850份真实材料中的冲突正例。人工参照未确认，不报告准确率或统计显著性。当前只支持流程可运行、部分处置可修订的开发观察。
