# 基于提议者—审核者机制的知识库增量维护实验

**FinRisk 决赛展示汇报稿**
**实验日期：2026年10月24日**
**当前进度：已完成20份开发样本，100份完整实验尚未全部运行。**

> **核心结论：** 本轮验证了“新材料先整理、再独立复核、证据不足则保留待核”的维护流程。20份材料形成14份新增候选、5份排除建议和1份待核结果，其中1份经过审核触发业务修订。针对旧知识矛盾、错误和替代关系的处理，仍需补充验证。

## 一、为什么开展这个实验

处罚案例知识库需要持续吸收监管部门新发布的材料。新文件到来后，需要判断：它是不是新的处罚案件？旧库是否已经收录？原文是否足以支持风险标签？是否存在需要纠正或更新的旧记录？

如果直接将模型生成的知识卡加入正式库，可能出现重复收录、主体归属错误、标签依据不足或过早排除材料等问题。因此，我们设计了提议者—审核者机制，在知识更新前增加独立复核环节。

本实验的目标，是检查这套机制能否形成**有原文依据、能够回查、可以说明处理理由的更新建议**。

本轮将旧库作为固定参照，重点观察新材料加入时的处理过程。旧库内部一致性是实验前提，不代表我们已经重新审核并证明了全部旧文书不存在问题。

## 二、实验材料如何安排

### 1. 旧库与新增材料的关系

我们以10,000份赛事文书作为基础库，以850份官网采集文书作为待更新材料池。先对850份材料进行脚本预检，再选出100份新材料开展分阶段实验。

**这100份全部是新材料。** 旧文书不占100份样本名额，而是供模型检索和核对的参照。每份新材料可能对应零份、一份或多份旧文书，因此不人为要求新旧文件按1∶1配对。

旧库检索范围覆盖完整的10,000份来源，模型只完整阅读与当前任务有关的候选旧文书，避免把全库全文一次性放入模型上下文。

### 2. 按新旧关系分层抽样

为了同时考察新增、关联核查和不确定情况，100份新材料按下表安排：

| 材料分组 | 100份实验计划 | 本轮开发样本 | 后续正式样本 |
|---|---:|---:|---:|
| 初筛没有明显同案线索 | 40份 | 8份 | 32份 |
| 初筛发现相关旧记录 | 40份 | 8份 | 32份 |
| 新旧关系或材料性质不明确 | 20份 | 4份 | 16份 |
| **合计** | **100份** | **20份** | **80份** |

“发现相关旧记录”只是检索线索，例如同一机构或相关主体曾经受罚，不能直接解释为同案、重复或矛盾。是否需要更新旧知识，仍要依据完整文书判断。

本轮先运行20份开发样本，检查流程与问题，再决定是否扩大到后续80份。另准备了16份合成受控检查材料，用于针对性检查重复、纠错、更正／替代和历史保护；这些参照目前仍待核定，尚未运行模型。

### 3. 本实验如何理解“冲突”和“过时”

历史处罚案例不会仅因时间较早就失去保存价值。本实验中的更新，应由具体证据触发：

| 新旧材料之间的情况 | 合理处理方向 |
|---|---|
| 同一机构在不同年份受到不同处罚 | 两案都保留，不能仅因年份或金额不同就认定矛盾 |
| 同一处罚决定被再次采集 | 关联来源，避免重复新增 |
| 知识卡中的主体、金额或事实与原文不符 | 核对证据后定点纠正，并保留修改历史 |
| 后续文件明确更正、撤销或替代原决定 | 更新相应状态或事实，保留前后关系和旧版本 |

因此，“整理过时知识”应理解为维护有证据支持的状态和版本关系，而不是按日期删除旧案例。材料身份或更正依据无法确认时，应保留待核。

## 三、提议者和审核者分别做什么

本轮统一使用 **GPT-6.1 Sol、低思考强度**，通过Codex原生角色运行，最多3个角色并行。提议者和审核者使用独立上下文，各自记录证据调用；审核者需要自己读取原文和检索，不能仅凭提议者的“已读”声明认定核查完成。

### 1. 提议者：整理事实并提出处理意见

提议者先读取新材料，再检索旧知识库，整理处罚主体、违法事实、处罚内容、风险标签和未知事项，并提出处理建议。

设计中允许以下处理类型：

| 处理类型 | 通俗含义 |
|---|---|
| 新增候选 | 将有依据的新事实整理为知识卡，等待确认 |
| 关联重复 | 同一处罚再次采集，保留新来源，不重复新增案件 |
| 纠正旧记录 | 旧知识卡与原文不一致，有证据支持定点修正 |
| 更正或替代 | 新文件明确更正、撤销或替代旧决定，记录前后关系 |
| 保留待核 | 现有证据不足，暂不作确定处理 |
| 范围排除 | 不符合本轮保险处罚审查范围，保留原文和排除理由 |

以上是机制的设计范围，不代表本轮已经实际验证了每一种处理能力。

### 2. 审核者：独立核对原文和处理理由

审核者重新读取新材料、检索旧库，并检查：

- 处罚主体、事实和处罚内容是否忠于原文；
- 风险标签是否具备必要的事实依据；
- 是否把个人受处罚直接理解为个人亲自实施全部行为；
- 是否遗漏重要事实或补入原文没有的信息；
- 重复、冲突和更新判断是否有充分的新旧证据；
- 证据不足时是否恰当保留未知。

审核者可以通过、要求修改、拒绝提案或要求进一步核实。本轮每份材料最多进行一次业务修订，避免无限往返。

**新增、排除和待核等所有处理意见，都进入审核环节。** “不新增”不会自动等于“已经正确去重”。

### 3. 程序校验与独立实验副本

模型输出后，程序检查引用是否能在原文中找到、标签是否来自官方字典、目标记录和版本是否匹配，以及修订次数是否超限。

通过本轮实验门禁的结果进入独立实验副本，保留提案、审核意见和修订历史。正式知识库没有被直接修改，候选记录仍保留待人工确认状态。

整体流程为：

```text
新材料 → 提议者读取、检索并提出意见
       → 审核者独立复核
       → 有实质问题时，进行一次修订与复审
       → 程序校验、保存实验候选与处置记录
       → 后续人工确认及正式构建（本轮未执行）
```

## 四、如何观察审核者的作用

我们保留了两份结果：

- **A组：** 提议者最初提交的版本。
- **B组：** 在同一份初稿上，经过审核及必要修订后的版本。

两组共用同一份初稿，减少重新生成造成的差异。比较时重点看审核者改动了什么、改动是否有依据，以及是否引入新的问题。

本轮先记录实际处置变化。由于人工质量参照尚未完成，不能把“发生了修改”直接解释为“修改正确”，也不能把模型审核通过率当成知识准确率。

## 五、20份开发实验取得了什么结果

### 1. 材料处置结果

20份材料均完成了提议和独立审核，最终形成以下建议：

| 最终处置建议 | 数量 | 结果含义 |
|---|---:|---|
| 新增候选 | 14份 | 整理为实验知识卡，等待后续确认 |
| 范围排除 | 5份 | 建议不加入本轮保险处罚检索，原文和理由保留 |
| 保留待核 | 1份 | 业务关联等信息不足，暂不确定接纳或排除 |
| **合计** | **20份** | **均有可回查的处理记录** |

审核者对其中1份提出了业务修改要求；提议者修订后，又进行了独立复审。

这里的“20份完成审核”，包括对排除和待核决定的认可，**不能表述为20份全部新增入库，也不能表述为准确率100%。**

### 2. 形成了哪些实验产物

| 产物或操作 | 实际数量 |
|---|---:|
| 新增候选来源 | 14份 |
| 实验案件卡 | 14张 |
| 实验行为卡 | 21张 |
| 完整读取的相关旧文书 | 6份，涉及5份新材料 |
| Codex原生角色任务 | 42个 |
| 已记录证据工具操作 | 143次 |

20份材料通常各运行一次提议和一次审核，共40个角色任务；其中1份额外经历修订和复审，因此总计42个。角色任务数不等于底层模型API请求次数。

14份新增材料在A、B两个实验版本中相同。审核造成的主要变化是1份材料从“排除”转为“待核”，因此不能仅根据新增数量评价Reviewer的作用。

这些知识卡采用本轮简化实验结构，尚未形成完整生产八表与BGE索引发布包。

## 六、典型案例说明

### 案例一：依据不足时，将确定排除改为待核

**材料：** 中国银河资产管理有限责任公司及相关责任人员的处罚信息，主要事实为“投后管理不到位”。

| 环节 | 处理意见 |
|---|---|
| 提议者初稿 | 判断为非保险范围，建议排除 |
| 审核者意见 | 原文没有明确说明业务类型，仅凭机构名称和案由，不足以确定保险关联，应保留待核 |
| 修订结果 | 改为待核，明确记录业务范围未知，不修改旧记录 |
| 最终复审 | 认可修订后的待核处理 |

**这个案例展示了什么？**

审核者能够对证据不足的确定性判断提出异议，并使系统转向保留未知。它展示的是对过早处置的约束；待核是否比排除更合适，仍需结合人工业务核验，不能仅凭模型复审认定已经纠错成功。

### 案例二：许可证相关材料也可能是处罚案件

**材料：** 人保寿险吉林省分公司“换领许可证超期”，原文明确记载警告并罚款1万元。

“换领许可证”容易被粗略规则视为许可或换证事项，但这份材料记载的是因超期受到行政处罚。提议者依据完整原文提出新增候选，审核者核对后认可。

**这个案例展示了什么？**

材料分类应同时检查违法事实和处罚内容，不能只依据“许可证”“换领”等词语决定排除。这里提议者初稿已经作出了相同处理，因此它属于正确处理过程的展示，不是Reviewer单独纠正初稿的案例。

## 七、程序与数据保护验证

除模型处置外，本轮还进行了以下检查：

| 检查 | 结果及解释 |
|---|---|
| 离线测试 | 54项通过，覆盖引用、目标版本、审核分支、共享预算与原子变更等 |
| 引用回读 | A/B实验投影均完成148处引用回读，检查引文与来源一致 |
| 旧查询回归 | 20条预定旧查询在轻量词项叠加视图中保持命中 |
| 撤销检查 | 验证实验变更可撤销，原始参照保留 |
| 资产保护 | 3,076个受保护文件哈希核验未变化 |
| 正式知识库 | 未修改，未切换应用当前版本 |

这些结果说明实验流程具备一定的可追溯性和数据保护能力。引用匹配只能证明“文字来自原文”，不能独立证明模型对业务含义的理解正确；旧查询回归也不是完整风险识别效果测试。

本轮主机观察窗口约39.2分钟，包含排队、工具调用和协调时间，不能当作纯模型推理耗时。使用Codex额度，没有调用DeepSeek。原生角色没有可用的逐任务token账单，因此不报告精确token数量或人民币费用。

## 八、目前能得出什么结论

### 已有结果支持的结论

1. **新材料可以经过完整的提议和审核流程。** 本轮20份均形成了最终处置建议，且有原文和审核记录可回查。
2. **系统能够保留不确定性。** 证据不足的材料可以进入待核，而不是强行接纳或排除。
3. **审核能够触发实际业务修订。** 本轮有1份处置意见发生变化，并经过再次审核。
4. **实验更新能够与正式库隔离。** 候选、引用和变更记录可以保留、回读和撤销，不必直接影响现有应用。

### 目前仍不能支持的结论

本轮没有形成得到验证的重复关联、旧记录纠错或更正／替代案例，因此不能声称已经证明“自动清除矛盾和过时知识”的能力。

同时，模型审核通过率不等于准确率。目前尚未完成独立人工参照，不能声称Reviewer显著提升了整体质量。

## 九、为什么没有立即扩大到80份

开发轮的程序处置数量达到预定门槛，但进一步回读发现：**8份“有相关旧记录”的材料中，只有3份实际完整读取了旧文书。** 其中D10、D13、D15形成了新增候选，却没有完整旧文对照。

这不等于已证明这些新增建议错误，但说明本轮还没有充分检查新旧关系。搜索摘要或未命中记录，不能替代针对相关旧案的完整核查。

因此，后续应先完成以下改进：

1. 对已有相关旧案线索的材料，提高候选检索与完整旧文阅读覆盖。
2. 优先依据文号、主体、处罚机关和具体事项判断身份，区分重复、不同处罚和明确更正。
3. 对模型建议进行人工核验，再评价审核前后的质量变化。
4. 核定16份受控参照后，单独检查纠错、更正／替代及历史保护能力。
5. 上述条件满足后，再运行已冻结的80份正式样本，保留本轮开发结果作为历史记录。

真实材料中如果没有足够的矛盾或更正案例，应如实报告。合成检查只能证明受控条件下的机制表现，不能计作从真实850份中发现的冲突。

## 十、可直接用于答辩的陈述

> 我们以10,000份赛事文书为基础，模拟新采集材料加入知识库的过程。为避免直接追加造成重复、标签依据不足或处置过早，我们设置了提议者和审核者两个独立角色：一个负责整理与提出更新意见，另一个负责核对原文和处理理由。
>
> 本轮先完成20份开发材料，形成14份新增候选、5份范围排除建议和1份待核结果。其中，审核者要求1份材料从确定排除改为待核，修订后通过复审。实验还生成了知识卡，完成引用回读和撤销检查，正式知识库没有被修改。
>
> 当前结果说明，新材料的整理、审核和有限修订流程能够运行，并能在证据不足时保留未知。针对旧知识的矛盾、错误和替代关系，本轮证据仍不足。下一步将加强相关旧文的完整核查，并通过独立人工核验和受控检查，再评估更大规模更新的效果。
