# 新旧知识库增量维护：20份开发实验

本实验模拟在 **10,000份赛事基础文书**上处理**850份新采集材料**：提议者整理更新建议，独立上下文的审核者核对原文与处理依据。使用原生Codex `gpt-6.1-sol / low`，最多3个角色并行，没有调用DeepSeek。

**本次只完成20份开发材料，结果为14份建议新增、5份建议范围排除、1份待核。未更新正式知识库；不是850份入库完成，也不是准确率100%。**

事后核读还发现：**D14、D20的排除理由需要补充核验**，不能将5份排除全部当作已经确认的正确结果。原始模型输出与计数保留，补充意见单独记录。

**维护流程：采集材料 → Proposer提出方案 → Reviewer复核／退回 → 生成人工待审维护包 → 人工批准 → 构建并验证新版本 → 发布启用。** 模型Reviewer批准仅表示形成建议，不能代替人工批准；本轮停在人工待审维护包和隔离验证阶段。

## 数据与结果

冻结的100份**都是新材料**，旧库始终是完整的10,000份只读参照。不是从新旧库混抽100份。

| 新材料分组 | 开发轮已运行 | 正式轮未运行 | 合计 |
|---|---:|---:|---:|
| 初筛无明显同案线索 N | 8 | 32 | 40 |
| 有相关旧记录线索 R | 8 | 32 | 40 |
| 身份或材料性质不明 U | 4 | 16 | 20 |
| 合计 | **20** | **80** | **100** |

相关线索不等于已证实同案、重复或冲突。16份合成受控参照按用户要求保持待核，未运行，不计入真实材料结果。冻结样本见[samples.json](samples.json)，基线记录见[baseline-manifest.json](baseline-manifest.json)。

| 指标 | 本轮观察 |
|---|---:|
| 形成双角色最终处置建议 | 20份 |
| 建议新增 / 范围排除 / 待核 | 14 / 5 / 1 |
| Reviewer触发业务修订 | 1份：D18从排除改为待核 |
| 原生角色任务 / 证据操作 | 42 / 143 |
| 实际完整核读的旧文 | 6份，涉及5份新材料 |
| R组有旧文完整核读 | 3 / 8 |
| 真实重复关联 / 旧记录纠错 / 替代 | 0 / 0 / 0 |

所有20份的最终建议均得到模型Reviewer认可，认可包含对“排除”“待核”的认可，不代表20份新增。A保留初稿，B使用审核后结果；两组均新增14份，知识卡数量没有增长，主要差异是D18的处置。不能据此宣称审核显著提高整体准确率。

## 当前结论

可以展示：新材料能完成提议、独立审核、一次有限业务修订、范围分流和隔离候选构建；证据不足时可以保留未知，引用和结果可追溯。

尚不能展示：自动清除矛盾与过时知识的真实效果、Reviewer准确率提升、850份正式更新完成。本轮没有验证这几类旧记录维护正例。历史处罚不能因日期较早就删除；旧库内部一致是实验假设，不是已证明事实。

正式80份暂不扩批。先补齐D10、D13、D15等新增建议的完整旧文对照，统一D14、D20与D18的范围判定证据门槛，再核定人工参照与受控检查。

## 离线复核

从仓库根目录运行，Python标准库即可；不联网、不调用任何模型、不修改正式库：

```powershell
python "docs/experiments/incremental-maintenance-20261024/verify_results.py"
```

检查文件SHA、20/80分组、14/5/1处置、42个角色输出与143次操作、源文SHA、6份旧文、A/B知识卡、D18修订和D14/D20事后待复核标识。原执行器54项离线测试在发布前重新运行通过，记录见[publication-validation.json](publication-validation.json)。引文回读是原主机验证记录，本脚本不重复进行语义审核。

这是**结果复核包**，不是可一键重新调用模型的执行器。实际模型身份与旧资产保护依赖原主机记录；公开SHA核验不能独立认证模型调用，也不能代替人工语义审核。完整基础资产见[knowledge-full-20261024 Release](https://github.com/wzz356/finrisk-agentic-rag/releases/tag/knowledge-full-20261024)，本目录不重复放入185MB的本机实验SQLite。

主机观察窗口约39.2分钟，含排队、协调与工具操作，不是纯模型推理时长。没有逐角色token账单，不报告精确token或人民币成本，见[资源说明](resources.json)。

公开副本保留来源URL、处罚文本、模型提案和失败边界，移除本机路径、内部调度身份及账户用量。转换与原始文件SHA见[provenance.json](provenance.json)，公开文件SHA见[checksums.json](checksums.json)。[隔离验证](shadow-verification.json)和[旧资产保护](protection-verification.json)是实验时的主机观察，跨机器不能据此重新检查私有原件。
