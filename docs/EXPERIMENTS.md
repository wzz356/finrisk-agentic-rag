# R1 / R2 / A对照实验工具

`scripts/agentic_dev30/experiment.py`包含离线prepare和有预算授权的execute；`paired_prefetch.py`控制共享首轮证据和材料间缓存边界；`retrieval_reliability.py`只读检查检索完整性。先运行各入口`--help`核对参数。

R1只有一次风险判定，R2运行固定多步，A可以根据缺口继续工具调用。三者的检索都包含DeepSeek重排，因此“一次判定”不等于整个系统只调用一次LLM。默认公开演示不启动这些真实实验。

## 外部数据要求

原调度器绑定30条已批准开发参照、每项输入文本与背景哈希、审批manifest、兼容知识快照、源码/提示/模型资产哈希，以及`resources/agent_rag/evaluation/dev30-human-reference-manifest.json`。这些真实材料、manifest及原始结果不随包发布，使用者须自行准备兼容文件；此入口不是任意评测集的一键运行器。不要编造审批或复制旧授权去运行新任务。

## 公平性与记账

显式启用paired-prefetch后，每材料先进行一次完整首轮检索，R1/A首轮证据一致；清理材料间缓存前须确认无未结束检索。公共检索不完整时整轮停止，不把缺失候选当完整排名。不同组独立判定，不共享模型答案。

公共召回实际费用计一次，方法独立部署成本估计另列。真实任务耗时与“公共检索＋各组任务”的合成估计分开；后者不是实测独立冷启动，也不能把缓存收益当Agent推理收益。已结束执行只读，不自动重跑；失败和未执行项保留，未知用量继续占预算。

## 结论边界

先检查工程完整性，再比较简单明显风险的中位耗时、复杂风险的标签/条件/证据正确性，并人工审查“追加证据是否改变了判断”。少量开发材料只支持探索性分析。格式合法、引用坐标对应和较长的轨迹都不等于语义准确；Agent未改善结果时应照实报告。当前最新先导仍中止，不能据此宣称优于一次判定RAG。
